# ADR-0008: A 股先行，美股后移植

- 状态: 已接受
- 日期: 2026-08-31
- 相关: [00-overview](../00-overview.md), [05-market-config](../05-market-config.md)

## 背景

两个市场的可行性正好互补：

| 维度 | A 股 | 美股 |
|---|---|---|
| 开户 | 简单 | 对大陆居民有门槛（跨境合规、购汇用途限制） |
| 数据 | akshare/tushare 免费或低成本 | Alpaca 免费档可用 |
| 交易 API | 门槛高（QMT/PTrade 需量化权限，通常 50 万资产级，**因券商而异需确认**） | Alpaca/IBKR 注册即用，有 Paper 沙盒 |
| 结论 | **可研究，难自动交易** | **可自动交易，难开户** |

需要决定从哪个市场开始。

## 决策

**A 股先做研究闭环（P0-P5，不接交易 API），美股在 P6 补执行闭环，各自条件成熟后接实盘。**

```
P0-P5  A 股    研究 + 建议 + Shadow Portfolio（SimulatedBroker）
P6     美股    Paper Trading，补全执行链路
P7a    美股    小资金实盘（开户完成后）
P7b    A 股    QMT 接入（量化权限达成后）
```

配套约束：**从第一天起市场特性外置为配置，代码中不出现市场判断分支。**

```python
# ❌ 禁止
if market == "CN":
    limit = 0.10

# ✅ 要求
limit = cfg.price_limit.for_security(sec, as_of)
```

## 理由

**执行层不是系统价值的主要来源。** 系统 90% 的价值在数据层、研究层、评估层。这些部分与市场无关。先在能拿到数据的市场把这些做好是理性的。

**A 股阶段的 Shadow Portfolio 本质上就是 Paper Trading。** 只是撮合由自己的引擎完成。这不是降级——它验证了除券商 API 之外的全部链路。

**但要注意它验证不了两件事**：券商 API 交互（只能模拟你以为的行为），以及撮合假设本身（用 `SimulatedBroker` 验证自己是循环论证）。这两项需要券商模拟环境，是 A 股实盘的硬前置。见 [ADR-0012](0012-cn-simulated-trading.md)。

**A 股的约束更严格，先做更保险。** T+1、涨跌停、无做空、100 股整手。如果引擎能正确处理 A 股，处理美股是简化。反过来则需要大量补充。

**避免被开户问题阻塞。** 如果先做美股，开户不成整个项目停摆。先做 A 股，开户是后续的加分项而非前提。

## 可移植性的现实评估

必须区分三类：

| 类别 | 占比 | 内容 |
|---|---|---|
| 完全复用 | ~70% | PIT 数据层、Agent 框架、Quant 骨架、风控框架、评估体系、UI |
| 需适配 | ~20% | Collector、行业分类映射、市场规则配置、BrokerAdapter |
| **不可复用** | ~10% | **策略逻辑本身** |

**最后一项必须清醒**：

| 市场 | 特征 | 常见异象 |
|---|---|---|
| A 股 | 散户占比高、情绪驱动 | 短期反转、小市值效应、题材炒作 |
| 美股 | 机构主导 | 动量持续、质量因子 |

同一因子在两个市场可能符号相反。所以"移植"指的是**工程框架移植，策略必须重新验证**。

这一点写进 Gate 6 的验收条件：**美股因子必须独立验证，不假定可移植。**

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 先做美股（数据和 API 都容易） | 被开户问题阻塞的风险；且 A 股约束更严格，后补更难 |
| 同时做两个市场 | 精力分散；两边都做不深 |
| 只做 A 股，不考虑美股 | 放弃了自动交易能力；且多市场抽象成本很低（配置驱动） |
| 只做美股，放弃 A 股 | 开户不确定；且 A 股是熟悉的市场，研究更有把握 |
| 先做 A 股但不考虑移植（后期再重构） | 后期重构成本远高于前期设计成本 |
| 做跨市场统一组合优化 | 需处理汇率风险、时区错配、相关性估计困难，收益不抵复杂度 |

最后一项的补充：**两个市场当作两个独立策略跑**。每个 `account` 有独立 `base_currency`，账户内不混币。汇率仅用于展示层折算。

## 后果

**正面**：
- 不被开户阻塞
- A 股严格约束使引擎更健壮
- 多市场抽象的边际成本很低（主要是配置文件）
- Shadow Portfolio 提供了 Paper Trading 的等价验证

**负面**：
- A 股阶段无法验证真实券商交互（延迟、拒单、部分成交的真实模式）
- 配置驱动增加了一层间接性
- 需要维护两套市场配置和风控配置

**必须接受的代价**：A 股阶段的"给建议"模式缺少真实反馈约束，存在选择性记忆的认知风险（R-21）。缓解手段是 Shadow Portfolio 的 append-only 强制记录。

## 配套的工程约束

| 约束 | 实现 |
|---|---|
| 市场特性外置 | `config/markets/{cn,us}.yaml` |
| 风控参数分市场 | `config/risk/{cn,us}.yaml` |
| 禁止硬编码市场常量 | CI 检查 |
| 行业分类不跨市场映射用于风控 | 风控分组必须用本市场原生分类 |
| 加市场不破坏既有结果 | 回归测试对比 `baseline_metrics.json` |
| 新市场接入清单 | [05-market-config](../05-market-config.md) 第 7 节 |

## 复审条件

- 若美股开户比预期顺利（P2 之前完成）→ 可考虑提前 P6，但不改变 A 股优先的数据和研究工作
- 若 A 股数据源持续不稳定，成本过高 → 重新评估市场优先级
- 若 A 股量化权限意外容易达成 → P7b 可提前，但仍在 P6 之后（需先验证执行链路）
