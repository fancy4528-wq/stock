# ADR-0011: 不建通用金融知识库，只沉淀自有判断历史

- 状态: 已接受
- 日期: 2026-08-31
- 相关: [17-knowledge-base](../17-knowledge-base.md), [ADR-0007](0007-risk-not-agent.md)

## 背景

系统有 pgvector 和 `knowledge/` 模块，自然会想到"给 Agent 灌输金融知识"：金融教科书、投资大师著作、券商研报方法论、A 股制度手册、技术分析形态图谱。

直觉上这会让 Agent"更专业"。

需要决定知识库里装什么。

## 决策

**不建通用金融知识库。知识库只装三类内容：**

1. **K2 历史文档全文**（年报 MD&A、风险因素、重大公告）— P2
2. **K3 自有判断历史**（过往 thesis + 关键假设 + 是否被证伪 + 实际收益）— P4
3. **K4 经验教训沉淀**（归因结论、已知失效模式，上限 50 条）— P4+

**明确不装**：金融概念定义、投资流派方法论、教科书策略、制度规则全文、历史牛熊案例、技术形态图谱。

制度规则走配置（`config/markets/cn.yaml`），本项目口径走 prompt 固定前缀（≤500 token）。

## 理由

### 一、成本上算不过来

一份 5 万字制度手册约 7 万 token。常驻 prompt 的话，按每日 40 次调用计，这一块就会吃掉 `daily_research` 的全部预算（$0.80/日）——换来的是模型本来就大致知道的内容。

即使走 RAG（`top_k=5`，每片 500 token），成本降到 ~2.5k token/次，但**收益仍然接近零**：检索出来的是通用定义，Agent 不需要它们。

### 二、灌输投资流派会制造系统性偏见 —— 这是最重要的理由

本项目的核心分工是：**量化因子回答"是什么"，Agent 回答"为什么"。**

把投资流派塞进 Agent，等于让 Agent 替量化层做本该由数据决定的判断：

```
知识库含大量价值投资材料
        ↓
StockAgent 分析高估值成长股
        ↓
倾向给出"估值偏高，谨慎"的结论
        ↓
但该结论不来自当期数据，来自被灌输的先验
        ↓
Fusion 层以为收到了独立的 Agent 观点
        ↓
实际收到的是"知识库作者的观点"
```

后果：Agent 观点与量化信号的独立性被破坏。而 Signal Fusion 恰恰假设二者独立（见 [09-portfolio-risk](../09-portfolio-risk.md) 相关性陷阱）。这是一种**隐蔽的信号相关性**——比 R-05 记录的那种更难发现，因为它藏在 prompt 里而不在数据里。

这个理由与 ADR-0007（风控不做成 Agent）同源：**该由确定性逻辑决定的事，不要交给 LLM 的先验。**

### 三、教科书策略与市场有效性冲突

能被写进教科书并广泛复述的策略，基本已被套利掉。

让 Agent 熟读经典的净效果，很可能是让它**更自信地给出无 alpha 的结论**。这直接加剧两个已登记风险：

- R-06 事后合理化 —— 有了完整框架，编故事更顺畅、更可信
- R-24 误当赚钱工具 —— 输出看起来更专业，更容易被信任

**输出的专业感与预测力无关，但会影响人对它的信任度。** 这是负面效果。

### 四、真正的知识资产在别处

| 性质 | 通用金融知识 | 自有判断历史 |
|---|---|---|
| 可从预训练获得 | 是 | **否** |
| 别人也有 | 是 | **否** |
| 随时间增值 | 否（静态） | **是** |
| 可验证有效性 | 难 | **可以 A/B 测试** |

`decision_journal` 已经在记录每次判断的 thesis 和关键假设，`decision_outcome` 在回填实际结果。这两张表里的信息 **LLM 不可能知道，任何通用知识库也不会有**。

具体价值：

```
分析 600xxx 时可检索到：
  [2026-03-15] 看多：产能扩张落地
               关键假设：新产线 2026Q3 投产
               信心度 0.72
  [结果] 20 日超额 -8.1%，假设被证伪（延期至 2027Q1）
  → 教训：该公司产能指引偏乐观，执行力指引应打折扣
```

### 五、制度规则必须精确，RAG 保证不了

涨跌停幅度、T+1、ST 规则这类知识**必须精确**。RAG 可能检索不到、可能命中过期版本、可能被模型误读。

正确做法是配置化，且**规则参与计算而非推理**：回测引擎和风控引擎读配置执行，Agent 只需看到 `is_limit_up = true` 这个算好的字段，不需要"知道"阈值是 10%。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 灌入金融教科书 | 预训练已掌握；占预算换零增益 |
| 灌入投资大师著作 | 制造系统性偏见，破坏信号独立性 |
| 灌入券商研报方法论 | 同上，且研报本身有立场 |
| 灌入 A 股制度规则全文 | 精确性要求高，RAG 不可靠，应配置化 |
| 灌入历史牛熊案例 | A 股 30 年仅 ~4 轮，样本太少，归纳不可靠 |
| 灌入技术分析形态图谱 | 形态识别应由量化层做，有效性存疑 |
| Fine-tune 一个"懂 A 股"的模型 | 成本高、数据不足、无法验证收益、更新困难 |
| 把 prompt 写成投资框架长文 | 上述方案的变体，成本更高 |
| P2 就做历史 thesis 检索 | 库里只有几十条无结果 thesis，无信息量还要付费 |

## 后果

**正面**：
- 知识库成本可控（Embedding 本地跑，零 API 成本）
- Agent 观点保持与量化信号的独立性
- 知识资产随时间增值且独有
- K1 口径 ≤500 token，可被 prompt 前缀缓存

**负面**：
- Agent 对 A 股特殊制度的理解依赖预训练，可能有偏差
- 需要在 prompt 里显式提示制度约束（如"该股为科创板，涨跌幅 20%"）
- K3 要等到 P4 才有价值，前期没有"记忆"能力
- K4 需人工维护，有膨胀风险（故设 50 条上限）

**必须接受的代价**：Agent 可能偶尔说出与 A 股制度不符的话（如提到"做空"）。缓解方式是在 prompt 约束中明确禁止项，并在输出 schema 校验层拦截，而非灌输制度手册。

## 两个必须注意的陷阱

### 陷阱一：知识文档自身的 PIT

**知识会过期。** 2020 年注册制规则不适用于 2018 年案例。若回测 2018 年时检索到 2024 年的监管规则，这是很难发现的未来函数。

因此 `document_chunk` 增加 `expires_at` 列，检索需双向过滤：

```sql
WHERE visible_at <= :as_of
  AND (expires_at IS NULL OR expires_at > :as_of)
```

### 陷阱二：历史 thesis 片段的 visible_at

thesis 片段的内容包含"结果"，而结果在写下 thesis 的当时不可知。

```
❌ visible_at = as_of_date              （thesis 写下时间）
✅ visible_at = 结果确认时间             （as_of + 20 交易日）
```

搞错这一点直接造出未来函数：回测中 Agent 会读到"这个判断后来错了"。

K4 归因结论同理：2026 年做的归因，不能被 2025 年的回测检索到。否则等于用后来总结的规律回测过去——**最常见的过拟合伪装形式**。

## 复审条件

- 若 P4 的 A/B 测试显示历史检索**未提升准确率**（只提升一致性），关闭该功能——那是锚定不是学习
- 若 Agent 频繁出现 A 股制度性错误（如提及做空、T+0），考虑将极简制度约束加入 prompt 固定前缀（**仍不建知识库**）
- 若 K4 条目逼近 50 上限，删旧不加限
- 若某类通用知识被证明确实缺失且影响判断，先尝试途径 B（配置）或 C（工具），RAG 是最后选择
