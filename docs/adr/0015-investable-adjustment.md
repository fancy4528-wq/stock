# ADR-0015: 投入额调整建议 —— 被动响应默认开，主动推送默认关

- 状态: 已接受
- 日期: 2026-09-01
- 相关: [09-portfolio-risk](../09-portfolio-risk.md) 第 11 节, [ADR-0013](0013-cold-start-portfolio.md), [14-risk-register](../14-risk-register.md) R-24/R-43

## 背景

冷启动支持用户只投一部分（`investable`）。自然的延伸问题：**当系统判断"形势好"时，能不能主动推送，问用户要不要提高 `investable` 上限？**

这个问题看似是 `REC_STANCE_UP`（stance 转好时在 investable 内追加）的延伸，实则跨过了一条关键的线：

| | `REC_STANCE_UP` | 本 ADR |
|---|---|---|
| 动的钱 | `investable` 内留的现金 | **`investable` 本身**（动到未投入资金） |
| 性质 | 执行用户已承诺的投入 | **建议用户改变承诺、投入更多本金** |

**"建议用户投入更多本金"是整个系统里比荐股更敏感的动作。** 它不是"买哪只"，而是"你该往股市放多少钱"。

## 决策

**采用分级方案（用户选择 C）：**

1. **被动响应默认开启** —— 用户主动问"现在适合提高投入吗"，系统给带完整反面信息的评估。
2. **主动推送默认关闭** —— 需用户像开实盘一样显式开启；开启后必须满足六条约束。
3. **任何模式都不给具体投入金额** —— 投入多少本金取决于用户整体财务状况，超出系统能力范围。

## 理由

### 一、为什么主动推送危险到必须默认关闭

**顺周期助推。** "系统觉得形势好"往往对应市场已涨了一段——即**估值更高、风险更大**的时候。此时建议用户多投钱，是在系统性地放大顺周期行为。散户亏损很大一部分正是"行情好时加仓、回调时割肉"。一个会主动喊"形势好，加钱"的系统，是在帮用户追高。

**利益冲突观感。** "建议你多投钱"在观感上接近诱导交易，把系统从研究工具往"劝你多投入的东西"推。即便纯自用，这个倾向本身值得警惕。

所以主动推送不能默认开——它必须是用户在充分知情下的主动选择。

### 二、为什么开启后必须双向

只在"形势好"时推"可加码"，是单向助推，等于内建了追高偏差。**要做就双向**：形势好提示"可考虑加码"，形势差也提示"可考虑降低投入/留更多现金"。

双向的意义不只是公平，而是**让这个功能的净效应接近中性**——它提供市场位置信息，而不是单方向地催投入。

### 三、为什么触发信号是机会质量而非涨幅

最直觉的触发是"最近涨得好"。这恰恰是错的——**涨幅高是该谨慎的信号，不是加码的信号**。

正确的触发是机会质量：**高分且便宜的标的多不多**。

```python
def opportunity_quality(scores, valuations, cfg) -> float:
    high_score = [s for s in scores if s.fused >= cfg.min_score]
    cheap = [s for s in high_score if valuations[s.symbol].pct_rank < 0.40]
    return len(cheap) / len(scores)      # 不含任何近期涨幅项
```

"便宜的好标的变多"才是加码的合理理由；"最近涨得好"是追高。

### 四、为什么不给具体金额

投入多少本金取决于：收入稳定性、其他资产、负债、家庭支出、风险承受度、投资期限。**这些系统一概不知道。** 在信息严重不全的情况下给"建议加投 5 万"，是不负责任的。

所以系统只提供它真正知道的一个维度——**市场位置**（估值分位、距高点、历史信号后的表现分布），把"投多少"的决策留给用户。被动响应的输出必须明确声明这一点。

### 五、为什么被动响应可以默认开

被动响应由用户发起——用户已经在想加码，系统不是在催，而是在他决策前提供客观依据（尤其是反面信息）。这比用户凭感觉决定要好，风险也低得多，符合研究工具定位。

关键在于被动响应的输出要**先展示反面信息**（当前估值偏高、历史下跌概率），而不是先给鼓励。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 主动推送默认开启 | 顺周期助推，系统性放大追高行为 |
| 只在形势好时推"可加码" | 单向助推，内建追高偏差 |
| 触发信号用近期涨幅 | 涨幅高恰恰该谨慎，用它触发等于追高 |
| 给具体投入金额建议 | 系统不知道用户整体财务状况，不负责任 |
| 完全不做（连被动响应也不给） | 用户想加码时凭感觉决定更糟；提供客观依据有价值 |
| 复用 `REC_STANCE_UP` 一并处理 | 二者动的钱性质不同（承诺内 vs 改变承诺），混淆会导致自动动用未投入资金 |

## 后果

**正面**：
- 用户加码前能看到市场位置与历史风险
- 双向设计避免单向助推
- 默认配置下系统不会主动催用户投钱

**负面**：
- 被动响应仍可能被用户当成"系统说可以加"（尽管输出强调不给金额建议）
- 主动推送即使默认关，其存在本身仍是一个需要持续审视的功能
- 机会质量信号的有效性未经验证（需 shadow 数据支撑）

**必须接受的现实**：即使做了全部约束，"系统提示可加码"仍可能被用户简化理解为"系统看多"。这是这类功能无法完全消除的风险。所以默认关闭主动推送，是把这个风险的触发权交给用户。

## 复审条件

- 若开启主动推送的用户中，加码后 60 日亏损比例显著高于未加码时段，**关闭该功能**
- 若被动响应的输出被用户反馈"感觉像在鼓励我投钱"，重审文案，强化反面信息前置
- 机会质量信号若长期与后续收益无相关性，移除主动推送触发
- 接入实盘 API 后，本 ADR 不变——投入本金决策永远不自动执行
