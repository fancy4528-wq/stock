# ADR-0005: 强制模型演进顺序

- 状态: 已接受
- 日期: 2026-08-31
- 相关: [07-quant-engine](../07-quant-engine.md), [12-roadmap](../12-roadmap.md) Gate 3

## 背景

预测模型有多种选择：从简单的移动平均到 Transformer。直觉上应该用最强的模型。

但存在一个根本问题：**如果直接上复杂模型并得到不错的回测结果，你无法判断这个结果来自哪里。**

可能来自：
- 模型真的有效
- 某一个强因子（模型只是包装）
- 数据泄漏（管道 bug）
- 过拟合

## 决策

强制按此顺序，每级必须有完整评估结果才能进入下一级：

| Level | 模型 | 准入条件 |
|---|---|---|
| L0 | Buy & Hold / 等权池 | — |
| L1 | 单因子排序 | L0 完成 |
| L2 | 多因子线性组合（等权 / IC 加权） | L1 有 ≥5 个通过测试的因子 |
| L3 | Logistic Regression / Ridge | L2 结果可复现 |
| L4 | **LightGBM** | L3 完成，**L4 样本外必须优于 L2** |
| L5 | XGBoost / CatBoost 对比 | L4 稳定 |
| L6 | 集成 | L5 完成 |
| L7 | LSTM / Transformer | L6 完成 **且有明确假设说明为何序列模型会更好** |

## 理由

**L1 单因子测试的真正价值不是找因子，而是验证管道正确。**

如果单因子回测的结果与独立计算的 IC 分析不一致，说明回测引擎有 bug。这是发现管道错误最有效的手段。跳过 L1 直接上 ML，管道 bug 会被复杂模型掩盖。

**L2 等权组合是判断复杂度价值的标尺。**

如果 LightGBM 只比等权多因子好 5%，那这 5% 可能是噪声，而复杂度的代价（可解释性、维护成本、过拟合风险）是确定的。

**没有 baseline 就无法回答"值不值得"。**

问题"Transformer 比 LightGBM 好多少"只有在有 LightGBM 结果时才有意义。而"LightGBM 比等权好多少"只有在有等权结果时才有意义。

**深度学习在表格类金融数据上通常不占优势。**

L7 的门槛设为"必须说明为何序列模型会更好"，是因为：
- 参数量大，过拟合风险高且难察觉
- 训练成本高，迭代慢
- 可解释性差，出问题难排查
- 大量论文声称有效，但能稳定跑赢 GBDT 的极少

如果答不出"你假设序列中有什么结构是 GBDT 学不到的"，就不做。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 直接上 LightGBM | 无法归因效果来源；管道 bug 会被掩盖 |
| 直接上 Transformer | 同上，且过拟合风险更高 |
| 并行尝试多个模型择优 | 这是数据窥探。多次尝试后选最好的，等于在测试集上优化 |
| 只做 L0-L2 不上 ML | 放弃了非线性关系的建模能力，过于保守 |
| 用 AutoML | 黑盒搜索大量模型 = 大规模数据窥探 |

## 后果

**正面**：
- 每一级的价值可量化
- 管道 bug 能被及早发现
- 过拟合风险受控
- 有完整的对照体系

**负面**：
- P3 阶段耗时更长（4-6 周而非 2 周）
- 需要为"不会最终采用"的模型写代码
- 心理上会觉得在做"低级"的事

**必须接受的可能结论**：L4 未能显著优于 L2。此时正确做法是采用 L2（简单的等权多因子），而不是继续往 L5/L6/L7 尝试直到某个模型看起来更好。后者是过拟合。

## 配套措施

| 措施 | 说明 |
|---|---|
| `param_search_count` 记录 | 每次调参累计，写入 `backtest_run` |
| 封存期 `HoldoutGuard` | 只能用一次 |
| 每级结果记入 `baseline-results.md` | 后续对比的依据 |
| 特征重要性稳定性检查 | 各 walk-forward 轮次间应一致 |

## 复审条件

- 若某级模型明显不适用于当前问题（如 L3 线性模型对高度非线性关系），可缩短该级的投入但不能跳过（仍需记录结果作为对照）
- L7 的门槛不降低
