# ADR-0012: A 股模拟盘的取舍——不用免费模拟炒股，券商模拟环境为实盘硬前置

- 状态: 已接受
- 日期: 2026-08-31
- 相关: [10-execution](../10-execution.md) 3.0/3.4 节, [12-roadmap](../12-roadmap.md) P7b, [ADR-0006](0006-broker-abstraction.md), [ADR-0008](0008-cn-first-us-later.md)

## 背景

"接实盘之前要不要用 A 股模拟盘测试"看起来是一个问题，实际是三个不同的东西被混为一谈：

| | 免费模拟炒股 | `SimulatedBroker`（自建） | 券商模拟交易环境 |
|---|---|---|---|
| 例子 | 同花顺/东财模拟炒股 | 本项目组件 | QMT / PTrade 模拟 |
| 有 API | **否**（只能手工点） | 是（自己的） | **是**（与实盘同接口） |
| 撮合真实度 | 低（多数报价即成交） | 取决于我的假设 | 接近实盘 |
| 验证券商 API 交互 | 否 | **否** | **是** |
| 验证撮合假设 | 否 | 否（它就是假设本身） | **是** |

三者的结论完全不同，必须分开决策。

## 决策

**三条：**

1. **不使用免费模拟炒股。** 无 API + 撮合过松，无价值且有害。
2. **`SimulatedBroker` + Shadow Portfolio 覆盖 P0-P5 的全部验证需求。** 无需券商模拟环境。
3. **券商模拟交易环境是 A 股实盘的硬前置**（Gate 7b），并把 P7b 拆成两段：
   - **P7b-1** 模拟环境验证 + 撮合假设校准（**可与 P2-P6 并行**）
   - **P7b-2** 实盘（视权限条件）

## 理由

### 一、免费模拟炒股无价值且有害

| 问题 | 说明 |
|---|---|
| 无 API | 只能手工点单，验证不了程序化链路——**而这恰恰是唯一需要验证的东西** |
| 撮合过松 | 多数报价即成交、不排队、无滑点 |
| 已被覆盖 | 策略层面的模拟，Shadow Portfolio 做得更严格 |

第二条是"有害"而非仅"无用"：撮合过松会让人以为涨停能买进、大单没有滑点，**产生虚假信心**。这与 R-24（误当赚钱工具）同向叠加。

### 二、Shadow Portfolio 已覆盖除券商 API 之外的全部链路

[ADR-0008](0008-cn-first-us-later.md) 已确立："A 股阶段的 Shadow Portfolio 本质上就是 Paper Trading，只是撮合由自己的引擎完成。"

它验证了：数据 → 因子 → Agent → Fusion → Portfolio → Risk → 订单生成 → 持仓跟踪 → 归因。

而且比免费模拟盘**更严格**：`SimulatedBroker` 强制检查涨跌停不可成交、T+1、停牌，并记录未执行项（涨停买不进是真实的机会损失）。

所以 P0-P5 不需要券商模拟环境。剩下没验证的只有两件事：

| 未验证项 | 为什么自建模拟器做不到 |
|---|---|
| 券商 API 交互 | 订单状态机、拒单码、部分成交、撤单竞态、断线重连、对账差异 —— **你只能模拟你以为的行为** |
| 撮合假设本身 | `SimulatedBroker` 就是假设的实现，用它验证自己是循环论证 |

### 三、撮合假设从未被真实结果验证过 —— 这比 API 验证更重要

`SimulatedBroker` 里有一批假设，而**回测和 Shadow Portfolio 的全部结论都建立在它们之上**：

| 假设 | 依据 | 被真实撮合验证过 |
|---|---|---|
| 涨停价不可买入 | 常识推断 | **否** |
| 跌停价不可卖出 | 常识推断 | **否** |
| 停牌期间订单被拒 | 常识推断 | **否** |
| 单笔不超过当日成交量 X% | 经验取值 | **否** |
| 集合竞价成交价与优先级 | 规则文档 | **否** |
| 部分成交剩余处理 | 自行设计 | **否** |
| 市价单实际成交价范围 | 滑点模型假设 | **否** |

**单元测试只能验证代码符合我的假设，无法验证假设符合现实。**

R-04（涨跌停成交假设错误）标注为"高概率/严重/P0 必须解决"，但 P0 的手段只有 `is_limit_up` 字段和单元测试——都是在验证代码符合假设，不是验证假设符合现实。这是 R-04 的**残余风险**，且现有文档此前没有承认它。

唯一解法是拿真实撮合结果做对比：

```
同一组订单 ──┬──▶ SimulatedBroker   → fills_sim
             └──▶ 券商模拟环境       → fills_real
                        ↓
                逐项对比，记录偏差
                        ↓
        若某项假设错误 → 修正 SimulatedBroker
                       → ★ 重跑全部历史回测
                       → 若结论翻转，此前评估全部无效
```

**最后一条是这件事真正的价值：它可能推翻已有结论。越晚做，需要推翻的越多。**

这个测试很便宜（一组订单 + 一次对比），价值很高（可能证伪整个评估体系的基础）。

### 四、原路线在 A 股/美股之间不对称

拆分前的路线：

```
P7a 美股实盘  前置: Gate 6 + 账户可用 + Paper 连续 1 个月无异常   ✅
P7b A股 API   前置: 券商量化权限 + 程序化交易报告                ❌ 无模拟要求
```

**这是不对称的，且方向错了。** A 股的规则比美股复杂（T+1、涨跌停、多板块不同幅度、ST 规则），`QMTAdapter` 的技术栈风险也高于 Alpaca REST API（Windows 进程、IPC、公开文档少）。准入应该更严，不是更松。

### 五、`QMTAdapter` 不应首次上线就接实盘

它是全项目工程风险最高的组件。原路线里它**首次运行即在实盘环境**——把最不确定的组件放在最高风险的位置。

拆出 P7b-1 后：等权限达成时，接实盘的是"已在模拟环境跑了一个月的组件"，而不是"新代码"。

### 六、P7b-1 可能不占关键路径

**待核实**：券商模拟交易环境的准入门槛是否低于实盘量化权限（部分券商对模拟环境要求较松）。

若门槛较低：

```
现状假设：P0-P5 → P6 美股 Paper → P7b QMTAdapter 首次上线即实盘   ⚠️ 风险集中
若可提前：P0-P5 ─┬─ P6 美股 Paper → P7b-2 实盘
                 └─(并行) P7b-1 QMT 模拟环境验证 + 撮合校准
```

这是**把工程风险从关键路径上挪走**的机会，且撮合校准越早做，需要推翻的历史结论越少。值得优先向券商核实。

若门槛相同，P7b-1 就只能等到权限达成后做——但仍然是实盘的硬前置。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 用同花顺/东财模拟炒股验证策略 | 无 API 验证不了程序化链路；撮合过松制造虚假信心 |
| P0-P5 就接券商模拟环境 | Shadow Portfolio 已覆盖，多这一层无增益且分散精力 |
| 完全跳过模拟环境，权限达成即接实盘 | `QMTAdapter` 首次上线即实盘，风险集中；撮合假设永不被验证 |
| 只做 API 验证，不做撮合校准 | 撮合假设是回测结论的基础，比 API 更根本 |
| 撮合校准设通过门槛（如偏差 < 0.3%） | **会把校准变成过拟合**——调参数去满足门槛，见下 |
| 用历史成交数据反推撮合规则 | 只能看到成交的，看不到"被拒的订单"，样本有偏 |
| 靠阅读交易所规则文档确认假设 | 文档与实际撮合实现可能有差异；且无法覆盖券商侧的额外限制 |

## 关键设计：校准不设通过门槛

**偏差只要求记录，不设门槛。**

理由：目的是**知道偏差多大**，不是**让它变小**。设个门槛然后调参数去满足它，等于把校准变成另一种过拟合——这与 ADR-0005（强制模型演进顺序）防范的是同一类错误。

正确的处理流程：

```
偏差小（成交价 MAE < 0.5%，涨跌停行为一致）
    → 记录，继续

某项假设完全错误（如涨停实际可以部分成交）
    → 修正 SimulatedBroker
    → ★ 重跑全部历史回测
    → 对比结论是否改变
    → 若结论翻转，说明此前的全部评估无效
```

最后一步已写入 [12-roadmap](../12-roadmap.md) 第 6 节退出条件：**"撮合校准显示假设严重错误且修正后结论翻转 → 回到 P4 重新评估，此前全部结论作废。"**

这是最不想触发但必须预设的条件。

## 后果

**正面**：
- A 股与美股的实盘准入对称（Gate 7b ↔ Gate 6）
- `QMTAdapter` 有独立的验证阶段，不在实盘首次运行
- 撮合假设可被证伪 —— R-04 的残余风险有了应对
- P7b-1 可能并行，不占关键路径
- 明确排除了免费模拟炒股这条歧路

**负面**：
- 多一个阶段（2-3 周）
- 依赖券商模拟环境可得（门槛未知）
- 校准可能推翻已有回测结论（但这是发现问题，不是制造问题）
- 停牌场景的校准可能需要等待时机（持仓股恰好停牌）

**若模拟环境完全不可得**：P7b-2 的准入需要另找替代方案，或接受"首次上线即实盘"的风险并把初始资金压到极小（如单笔 100 股）。这种情况下应在 ADR 中补记。

## 校准的最低要求

| 项 | 要求 |
|---|---|
| 订单样本 | ≥ 200 笔，覆盖买/卖、限价/市价 |
| 涨跌停场景 | ≥ 5 次真实涨跌停订单尝试 |
| 停牌场景 | ≥ 1 次（可能需等待时机） |
| 时段覆盖 | 集合竞价、连续竞价、尾盘 |
| 产出 | 一份 `MatchingCalibration` 记录 + 未覆盖场景的诚实清单 |

数据结构见 [10-execution](../10-execution.md) 3.4 节。

## 复审条件

- 若券商模拟环境门槛经核实低于实盘权限，把 P7b-1 提前到 P2 之后并行
- 若模拟环境完全不可得，重新评估 P7b-2 的准入方案
- 若校准发现假设严重错误，触发 [12-roadmap](../12-roadmap.md) 第 6 节退出条件
- 每次修改 `SimulatedBroker` 撮合逻辑后，需回归校准
