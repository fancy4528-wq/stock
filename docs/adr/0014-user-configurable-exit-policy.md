# ADR-0014: 止盈止损 —— 用户可配阈值 + 系统兜底地板

- 状态: 已接受
- 日期: 2026-09-01
- 相关: [09-portfolio-risk](../09-portfolio-risk.md) 4.2a, [15-monitoring-alerts](../15-monitoring-alerts.md), [ADR-0007](0007-risk-not-agent.md)

## 背景

原设计里止盈止损是零散的：

- 监控层 `PX_STOP_LOSS` 硬编码 -8% 提醒
- 监控层 `PX_TAKE_PROFIT` 硬编码 +20% 提醒
- 风控层 `DD_005` 单标的 -20% 强制减仓（标注"可配置关闭"）

三个问题：

1. **阈值硬编码。** 止损线因人而异——风险承受度、持仓成本、税费敏感度、投资期限都不同。固定 -8% 对谁都不合适。
2. **策略真空。** -8% 提醒和 -20% 强制减仓之间隔了 12 个点，中间没有连贯的个股纪律。
3. **止盈几乎没有策略。** 只有一个 +20% 提醒，没有分批、移动、目标价。

## 决策

**三条：**

1. **个股止盈止损阈值开放给用户自定义**（`config/user/exit_policy_cn.yaml`），支持 fixed / trailing / atr / staged 四种。
2. **系统对用户阈值做边界校验**，越界拒绝配置并提示（止损限定 -3% ~ -30%）。
3. **区分两个层次**：用户策略是纪律（可关、可调、给建议），`DD_005` 是系统兜底（不可关、固定 -25%、hard 减仓）。

止盈止损产出**建议不自动卖出**（A 股阶段），与 ADR-0007 一致。

## 理由

### 一、为什么阈值必须可配

固定阈值隐含了一个假设：所有用户的风险偏好相同。这个假设是错的。

- 一个把这套系统当长线研究工具的人，可能根本不想要 -8% 止损（正常波动就触发）
- 一个短线用户可能想要 -5% 紧止损
- 持仓成本不同，同样的现价对不同人是浮盈或浮亏

所以阈值是**用户属性**，不是系统常量。硬编码等于替用户做了本该他自己做的风险决策。

### 二、为什么要区分"用户策略"和"系统兜底"

如果全部交给用户配置，会有人把止损关掉或设成 -80%，然后某只票跌到腰斩还不动。系统需要一个**用户无法突破的地板**。

```
用户止损 -10%   ──触及──▶  建议卖出（可确认/可忽略）
                              │ 用户忽略，继续跌
DD_005 -25%    ──触及──▶  强制减仓 50%（兜底，不可忽略）
```

两者目的不同：

| | 用户策略（4.2a） | DD_005（hard） |
|---|---|---|
| 目的 | 用户的进出场纪律 | 防止单票拖垮组合 |
| 可否关闭 | ✅ | ❌ |
| 阈值 | 用户设 | 固定 -25% |
| 动作 | 建议 | 强制减仓 |

所以把原 `DD_005` 从"-20%，可配置关闭"改为"-25%，纯兜底不可关"——它不再承担日常止损职责，只做极端兜底。日常止损让给用户策略。

### 三、为什么要边界校验

开放配置的代价是误设。缓解不是收回自由，而是**约束到合理区间**：

```yaml
bounds:
  stop_loss_min: -0.30    # 不得比 -30% 更松（否则等于没止损，交给 DD_005 也太晚）
  stop_loss_max: -0.03    # 不得比 -3% 更紧（噪声频繁触发）
```

越界时**拒绝配置并提示，不静默纠正**——静默纠正会让用户以为设成功了。

### 四、为什么仍是建议不自动执行

与 ADR-0007（风控判定归确定性代码）和六原则第 3 条（LLM 不得直接下单）同源，但这里的理由稍不同：**A 股阶段本就无 API**，能不能自动执行是伪命题。止盈止损触及后进入次日执行清单 / 盘中推送，由用户确认。

美股接 API 后（P6+）可选自动执行，但那是 execution 层的开关，默认关闭，不改变本 ADR 的策略定义。

### 五、为什么要快照策略

阈值可被用户随时修改。若不在触发时快照 `policy_snapshot`，事后复盘"当时为什么建议卖"会对不上——用户可能已经把阈值改了。`exit_signal.user_action` 还能分析用户是否遵守自己定的纪律。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 保持硬编码 -8% | 替用户做了风险决策，对多数人不合适 |
| 全部交给用户配置，无兜底 | 有人会关掉止损或设 -80%，单票可能腰斩 |
| 越界时静默纠正到边界 | 用户以为设成功，实际值不同，制造隐性错误 |
| 止盈止损做成 hard 风控规则 | 它是用户纪律不是系统底线；hard 规则不该因人而异 |
| A 股阶段就自动执行 | 无 API，伪命题；且违反人工确认闸门 |
| 用 LLM 判断该不该止损 | 止损是确定性规则，不需要也不应该用 LLM |

## 后果

**正面**：
- 用户按自己的风险偏好设纪律
- 消除了 -8% 与 -20% 之间的策略真空
- `DD_005` 职责清晰化（纯兜底）
- 支持移动止损、分批止盈等常见纪律

**负面**：
- 配置项增多，新用户需要理解 fixed/trailing/atr/staged
- 误设风险（用边界校验缓解）
- `exit_signal` 增加一张表与一层记录

**必须接受的现实**：用户可能设了止损又不遵守（`user_action = ignored`）。系统只能记录和提醒，不能强制——除非跌到 `DD_005` 的兜底线。这是"给建议不自动执行"的固有局限。

## 复审条件

- 若多数用户 `user_action` 长期为 `ignored`，说明提醒无效或阈值默认值不合理，需重新设计默认策略
- 美股接 API 后重新评估是否开放自动执行（届时 `DD_005` 兜底可自动触发）
- 若 `atr` 类型使用率极低，可考虑移除以降低配置复杂度
