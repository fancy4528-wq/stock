# 00 — 项目总览

## 1. 项目定位

QuantAgent 是一个**投资研究系统**，其次才是交易系统。

它有两条工作流：

| 工作流 | 时机 | 产出 | 特点 |
|---|---|---|---|
| **盘后批处理** | 每日 15:30-18:00 | 研究日报、板块排序、调仓建议 | 全股票池，被动查看 |
| **盘中监控** | 09:30-15:00 持续 | 持仓异动推送 | 仅持仓+关注列表，主动告知 |

两者互补：监控负责"救火"（发现需立即处理的情况），盘后负责"规划"（完整研究与调仓）。详见 [15-monitoring-alerts](15-monitoring-alerts.md)。

它的核心产出是：
- 每日板块排序与市场状态判断
- 有证据链的投资论点（Investment Thesis）
- 量化信号与概率预测
- 建议持仓（A 股阶段为人工执行清单，美股阶段为自动下单提案）
- **持仓需要调整时的主动推送**
- 可审计的决策日志与自我评估报告

### 1.1 三层能力分工

系统的设计基于一个判断：**LLM 和量化模型各有其不可替代的位置，混用会两头都做不好。**

| 层 | 承担者 | 职责 | 不该做什么 |
|---|---|---|---|
| 研究层 | LLM Agent | 决定研究什么、读文本提取信息、解释因果、生成论点 | 算仓位、判风险、下单 |
| 计算层 | Quant Engine | 因子计算、概率预测、回测、统计显著性 | 解释"为什么" |
| 决策层 | Portfolio + Risk Engine | 仓位大小、约束校验、否决权 | 被说服、被覆盖 |
| 执行层 | Execution Engine | 订单拆分、下单、对账 | 做投资判断 |

### 1.2 为什么这样分

LLM 的能力边界很明确：它擅长处理非结构化文本、建立跨领域关联、生成可读解释；它不擅长数值计算、概率校准、保持一致性。

把仓位计算交给 LLM 会得到一个无法回测、无法归因、每次运行结果不同的系统。把文本理解交给量化模型则需要重新发明 NLP。

所以边界是：**LLM 输出结构化的判断（score + confidence + evidence），量化和风控消费这些结构化输出做确定性计算。**

## 2. 目标

### 2.1 一年内的目标（按优先级）

| # | 目标 | 可验证标准 |
|---|---|---|
| 1 | 建成可信的 PIT 数据地基 | 任意历史时点可还原当时可见数据，回测无未来函数 |
| 2 | 每日自动生成市场研究报告 | 连续 20 交易日无人工干预产出 |
| 3 | Agent 结论可完全追溯 | 每个判断关联到具体数据行/新闻 ID/因子值 |
| 4 | **持仓异动主动推送** | 关键事件不漏报，日均 2-8 条，有用率 > 50% |
| 5 | **LLM 成本可控** | 日均 < $1.50，单条有用推送 < $0.30 |
| 6 | 量化预测优于基准 | 样本外 IC 显著 > 0，优于 Buy&Hold 与单因子 |
| 7 | Shadow Portfolio 积累 6 个月记录 | 自动记录、不可事后修改、含完整成本模拟 |
| 8 | **空仓用户可获得可执行的建仓方案** | 推荐在给定资金量下 100% 可执行，分批计划明确 |
| 9 | 系统可自我评估 | 能回答"我在什么情况下判断更准" |

### 2.2 明确的非目标

写清楚不做什么，比写做什么更重要。

| 非目标 | 原因 |
|---|---|
| ❌ 高频/日内交易 | 数据成本、延迟劣势、合规负担。定位是日线到周线级 |
| ❌ 抢新闻交易 | 公开新闻 alpha 在秒-分钟级衰减完，个人系统抢不到 |
| ❌ 秒级实时监控 | 监控延迟目标是分钟级。若某信号需秒级响应才有价值，不在能力范围内 |
| ❌ 全市场盘中监控 | 成本不允许。盘中只监控持仓 + 关注列表 |
| ❌ 预测具体价格 | 无意义且不可验证。只预测方向概率与收益分布 |
| ❌ 全市场覆盖 | MVP 阶段 50 支股票足够验证架构 |
| ❌ 期权/期货/衍生品 | 复杂度和风险都高一个量级 |
| ❌ 融资融券、杠杆 | 首版禁用 |
| ❌ 全自动无人值守实盘 | 至少到 P7 之前保留人工确认闸门 |
| ❌ 推送即自动执行 | 推送是建议，执行由用户或 Execution 层分别负责 |
| ❌ 对外提供服务/荐股 | 涉及投顾牌照，纯自用 |
| ❌ 追求 Transformer/RL 等前沿模型 | 没有 baseline 对照的复杂模型是自欺 |

### 2.3 反目标（明确要避免的失败模式）

| 失败模式 | 表现 | 防范机制 |
|---|---|---|
| 回测幻觉 | 回测年化 80%，实盘亏损 | PIT 数据 + 封存样本 + 涨跌停模拟 |
| Agent 事后合理化 | 报告写得好，无预测力 | Agent 输出 IC 检验（见 08 文档） |
| 参数过拟合 | 每次调参回测都变好 | 调参次数计数 + 封存期只用一次 |
| 建议自欺 | 只记住对的建议 | Shadow Portfolio 自动记录、append-only |
| **推荐被当作荐股** | 建仓清单在观感上等同投资建议 | 强制展示对照组 + shadow 实际成绩 + 全部推荐结果分布 |
| **推荐不可执行** | 小资金拿到一份买不起的清单 | `top_n` 由资金量推导 + 可执行性排除 + 整手取整 |
| **一次性建仓时点风险** | 全部成本基础由一天价格决定 | 分批建仓默认开启（4 批 × 5 日） |
| **推荐 vs 实际执行混淆** | 只买了涨的那几只，统计上"很准" | 归因用 shadow，不用用户实际执行 |
| **系统助推顺周期加码** | 形势好（估值高位）时催用户多投本金 | 主动推送默认关；开启后双向、基于机会质量非涨幅、不给具体金额 |
| **推送疲劳** | 推送太多，用户关掉通知 | 每日硬上限 + 冷却期 + 反馈驱动淘汰噪声规则 |
| **推送漏报** | 关键事件未推送 | 规则层零成本全覆盖 + 预算耗尽仍工作 |
| 复杂度失控 | 半年后代码无法维护 | 严格分层 + Gate 制度 + 不跳阶段 |
| 成本失控 | LLM 账单超预算 | 分项预算 + 调用前拦截 + 三级漏斗 + 模型分层 |

## 3. 成功标准

### 3.1 项目层面

系统成功的定义**不是赚钱**，而是：

> 能够持续产出可追溯、可归因、可验证的投资研究，并且我知道它在什么条件下可信、什么条件下不可信。

一个诚实地告诉你"我在高波动环境下准确率只有 38%"的系统，比一个回测年化 100% 但不知道为什么的系统有价值得多。

### 3.2 分层成功标准

| 层 | 成功标准 | 失败信号 |
|---|---|---|
| 数据层 | 完整性 ≥99%，PIT 可回溯，异常自动告警 | 数据缺口靠人工发现 |
| 研究层 | 结论 100% 有证据链，幻觉率 <5% | 报告出现数据库里不存在的数字 |
| 量化层 | 样本外 IC > 0.03 且 t 值显著 | 样本内漂亮，样本外归零 |
| 组合层 | 风控规则 100% 生效，无绕过路径 | 出现超限持仓 |
| **监控层** | 关键事件不漏报，有用率 >50%，规则层零成本 | 推送疲劳或漏报关键事件 |
| 执行层 | 对账零差异，异常路径全覆盖 | 出现重复下单或仓位不一致 |
| 评估层 | 能按市场状态/事件类型分解准确率 | 只有一个总收益率数字 |
| **成本** | 日均 < $1.50，单条有用推送 < $0.30 | 需要提高预算才能维持运行 |

## 4. 市场路线

### 4.1 为什么 A 股先行

| 维度 | A 股 | 美股 |
|---|---|---|
| 开户 | 简单 | 对大陆居民有门槛（跨境合规、购汇用途限制） |
| 数据 | akshare/tushare 免费或低成本 | Alpaca 免费档可用，深度数据付费 |
| 交易 API | 门槛高（QMT/PTrade 需量化权限，通常 50 万资产级，因券商而异） | Alpaca/IBKR 注册即用，有 Paper 沙盒 |
| 结论 | **可做研究，难做自动交易** | **可做自动交易，难开户** |

所以路线是：**A 股做研究闭环 → 工程框架成熟 → 美股 Paper 补上执行闭环 → 各自条件成熟后接实盘。**

### 4.2 阶段与市场对应

```
P0-P5   A 股    研究 + 建议 + Shadow Portfolio（无交易 API）
P6      美股    Paper Trading，补全执行链路
P7a     美股    小资金实盘（开户完成后）
P7b-1   A 股    券商模拟环境验证 + 撮合假设校准（可并行）
P7b-2   A 股    QMT 实盘（量化权限达成后）
```

**A 股与美股的实盘准入对称**：美股要过 Gate 6（Paper 连续 1 个月），A 股要过 Gate 7b（模拟环境连续 1 个月 + 撮合校准）。A 股规则更复杂，准入不应更松。

关于"模拟盘"需要区分三种东西：

| | 免费模拟炒股 | `SimulatedBroker`（自建） | 券商模拟环境 |
|---|---|---|---|
| 有 API | 否 | 是 | 是 |
| 对本项目价值 | **无，且有害** | 核心组件 | P7b-2 前必须 |

免费模拟炒股撮合过松（报价即成交、无滑点），会制造虚假信心；且无 API，验证不了程序化链路。见 [ADR-0012](adr/0012-cn-simulated-trading.md)。

### 4.3 可移植性预期

| 类别 | 占比 | 内容 |
|---|---|---|
| 完全复用 | ~70% | 数据层、Agent 框架、Quant 骨架、风控框架、评估体系、UI |
| 需适配 | ~20% | Collector、行业分类映射、市场规则配置、BrokerAdapter |
| **不可复用** | ~10% | **策略逻辑本身** |

最后一项必须清醒：A 股散户主导、反转效应强；美股机构主导、动量更持续。**因子有效性不可跨市场假定，必须各自重新验证。**

### 5.2 合规约束

| 约束 | 说明 |
|---|---|
| A 股程序化交易 | **已核实（2026-09-03）**：接实盘 API 自动交易即属程序化交易，无论资金/频率大小，须**"先报告、后交易"**——见 5.2a |
| 不得操纵市场 | 任何策略不得包含影响价格形成的意图 |

| 跨境证券投资 | 个人购汇用途申报不含证券投资；美股开户前需自行确认合规路径 |

### 5.2a 程序化交易报告制度（第 3 项核实结果）

**制度依据**：2023-09-01 沪深北交易所程序化交易报告制度；2026-01-12 起沪深股通投资者纳入报告范畴。

**触发条件**：只要"通过计算机程序自动生成或下达交易指令"，**无论资金量大小、频率高低**都须报告。本系统一旦接实盘 API 自动下单即属此列。

**"先报告、后交易"（硬约束）**：
- 会员客户首次开展程序化交易**前**，先向券商报告，券商核查后 5 个交易日内报交易所
- **必须在报告被接收确认后方可交易** —— 这是接实盘前的合规前置，不是可选项
- 报告信息重大变更（如换策略、改申报速率），在变更后下一自然月前 5 个交易日内变更报告

**报告内容**（本系统相关）：策略类型及主要内容（如"多因子选股 + 板块轮动"）、交易指令执行方式（如"信号触发市价/限价单"）、最高申报速率、单日最高申报笔数、交易软件信息（QMT/PTrade 名称版本）、账户与资金信息。

**高频额外要求不触发**：申报速率 > 300 笔/秒 或 单日 > 20000 笔才需额外报告（服务器所在地、测试报告、应急方案）。本系统日频、MiniQMT 基础版，**远低于高频阈值**，不涉及。

**工程含义**：
- 这是 **P7b-2（A 股实盘）的合规前置**，与量化权限申请同步办理（申请权限时一并向客户经理咨询报告填报流程）
- 实盘开关的"显式确认"（六条原则第 4 条）应包含"已完成程序化交易报告"的勾选项
- 系统需能导出报告所需信息（策略类型、执行方式、申报速率上限），见 R-45

### 5.3 技术约束

| 约束 | 说明 |
|---|---|
| 数据频率 | 日线为主；盘中监控用分钟级快照（仅持仓+关注列表）；不做 tick |
| 决策频率 | 日频调仓上限，避免高换手 |

## 6. 术语表

| 术语 | 含义 |
|---|---|
| PIT (Point-in-Time) | 按时点还原数据，只使用某时刻真实可见的信息 |
| `as_of(t)` | PIT 取数接口，返回 t 时刻可见的数据版本 |
| Look-ahead bias | 未来函数，回测中使用了当时不可得的信息 |
| Survivorship bias | 生存者偏差，样本只含存活至今的标的 |
| IC (Information Coefficient) | 预测值与实际收益的秩相关系数，衡量预测力 |
| ICIR | IC 均值 / IC 标准差，衡量预测稳定性 |
| Alpha 衰减 | 信号有效性随时间流逝而下降 |
| Shadow Portfolio | 影子组合，记录建议但不实际交易，用于验证 |
| Decision Journal | 决策日志，记录每次决策的完整上下文与后续结果 |
| Signal Fusion | 信号融合，将多来源评分合成单一决策分数 |
| Regime | 市场状态（risk-on / risk-off / 震荡等） |
| Thesis | 投资论点，对某标的/板块的完整判断陈述 |
| Evidence | 证据，支撑判断的可追溯数据引用 |
| Walk-forward | 滚动前向验证，按时间顺序训练-测试切分 |
| Turnover | 换手率 |
| Max Drawdown (MDD) | 最大回撤 |
| Universe | 股票池 |
| 申万行业 | 申银万国行业分类，A 股常用行业标准 |
| 概念板块 | 题材板块，情绪/资金驱动，区别于行业板块 |
| QMT / PTrade | 券商提供的量化交易客户端（迅投 / 恒生） |
| Kill switch | 紧急停止开关，一键停止所有自动交易 |
| 三级漏斗 | 监控层的成本控制结构：规则层(零成本) → 小模型 → 大模型 |
| L1/L2/L3 | 三级漏斗的层级。L1 纯规则，L2 小模型分诊，L3 大模型深度分析 |
| Trigger | 触发器，监控层判断"何时该看一眼"的规则 |
| Alert | 推送告警，含触发原因、当前状态、建议 |
| 冷却期 (Cooldown) | 同一触发器同一标的的最小推送间隔，防推送疲劳 |
| Prompt 缓存 | LLM 提供商对固定 prompt 前缀的缓存折扣机制 |
| 分项预算 | 按用途独立分配的 LLM 预算，互不挪用 |

### 7.1a 券商量化接口门槛（第 1、2 项核实结果）

**核实结论（2026-09-03）：模拟盘本身几乎无门槛，但"用 API 代码调用模拟盘"有门槛，且与实盘 API 同级。**

关键区分——这里最容易误解：

- **手动登录软件用模拟盘** ≠ **用 API 代码调用模拟盘**
- 用 Python 代码调 API 操作模拟盘（而非手动点按钮），必须先申请到量化接口权限
- **API 模拟调用与 API 实盘调用用的是同一套接口权限**，券商不因为是"模拟"就降低审核标准

量化接口申请的典型门槛：

| 门槛类型 | 具体要求 |
|---|---|
| 资金门槛 | **最低 5 万**（招商/东财）；国金 miniQMT 10 万；多数券商标准版 50 万（客户经理可协商） |
| 交易经验 | 6 个月以上 A 股真实实盘交易记录（跨券商可累计；开户/逆回购/货基不计入） |
| 风险测评 | **C4 或 C5**，C1-C3 无法开通 |
| 合规材料 | 《程序化交易风险揭示书》+ 交易所程序化报备问卷 |
| 账户与年龄 | 本人实名、无休眠/冻结/异常记录；18-70 岁线上办理 |

券商差异见 7.1b。国金 miniQMT / 招商 / 东财是对中小资金最友好的选择。

**这个结论推翻了第 1 项原先的乐观假设。** 原以为"模拟环境门槛较低 → `QMTAdapter` 可提前到 P2-P6 并行验证"。事实是：**拿到量化权限前，连模拟盘 API 都调不了**。所以：

- **权限达成前**：系统只能做「研究 + 建议」，交易靠**手动**在 QMT/Ptrade 里执行。这印证了 A 股阶段"不接 API、产出人工执行清单"（见 [09-portfolio-risk](09-portfolio-risk.md) 第 6 节）不是保守选择，而是**权限达成前唯一可行的路径**。
- **权限达成后**：模拟盘 API 与实盘 API 一起解锁，才进入 Paper 验证 → 实盘的自动化路径（实盘开关仍默认关闭，见六条原则第 4 条）。
- **A 股自动化链路无法端到端提前验证**：这是最高工程风险无法提前化解的确认。缓解：**用美股 Alpaca Paper 通道先跑通自动化链路**（注册即用、有沙盒），A 股用人工清单先验证研究质量，等权限达成再接 `QMTAdapter`。见 R-44。

| 山西证券 | 10 万 | 5-10 万 | 双平台低门槛 |

**国金 QMT 版本区分**（版本差异最大，对本项目最相关）：

| 版本 | 资金门槛 | 功能 |
|---|---|---|
| MiniQMT（基础版） | 10 万 | 基础 Python 接口、本地回测、实盘自动交易 |
| 完整版 QMT | 50 万 | Tick 级回测、全套 Python 接口、更丰富数据 |
| 极速柜台 LDP | 100 万 | 高频交易专用通道 |

**对本项目：MiniQMT（10 万档）功能完全够用**——支持 Python 策略、历史回测、实盘自动下单，无需追求 50 万完整版（本项目日频、不做 tick）。

**实操关键要点**：

- **不能 APP 自助开户** —— 自助开户不加量化白名单，APP 里找不到 QMT/PTrade 申请入口。必须先联系客户经理在后台录入白名单，才能解锁申请通道。
- **交易经验可跨券商累计** —— 6 个月实盘经验不要求在目标券商，系统自动调取历史成交，无需手动提交。
- **审核周期** —— 提交后通常 1-3 个工作日。
- **软件免费** —— QMT/PTrade 不收年费/授权费/开通费，仅正常交易佣金。
- **验资口径** —— 近 20 个交易日日均证券资产（含现金/股票/场内 ETF/可转债，不含融资负债）；达标后资金可转出，但每季度复核，长期低于门槛有权收回权限。
