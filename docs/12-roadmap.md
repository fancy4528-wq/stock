# 12 — 路线图与 Gate

## 1. 阶段总览

```
P0  数据地基            3-4周   ──▶ Gate 1
P1  因子与日报(MVP)      3-4周   ──▶ Gate 1
        │
        └──▶ Shadow Portfolio 启动（持续积累，与后续开发并行）
P2  多 Agent + RAG      4-6周   ──▶ Gate 2
P2a 规则监控与推送       1-2周   ──▶ Gate 2a   ★ 零 LLM 成本
P2b 智能分诊(三级漏斗)   2-3周   ──▶ Gate 2b
P3  Quant 模型          4-6周   ──▶ Gate 3
P4  完整回测与归因      3周+3月观察 ──▶ Gate 4
P5  组合与风控完整      3-4周   ──▶ Gate 5
P6  多市场 + Paper      3-4周   ──▶ Gate 6
P7a 美股实盘（小资金）   视条件
P7b-1 A股模拟环境验证    2-3周   ──▶ Gate 7b  ⚠️ 依赖量化权限，无法与 P2-P6 并行
P7b-2 A股实盘           视条件
P8  自适应系统          持续
```

**总周期：到能看到第一批可信结论约 7-10 个月。** 瓶颈是验证周期，不是编码速度。

### 为什么监控插在 P2 之后而非更早

监控需要两个前置条件：
- **持仓概念存在**（P1 的 Shadow Portfolio 提供）
- **新闻/公告数据已入库**（P2 的采集与事件抽取提供）

但 P2a 刻意**不依赖 P2 的 Agent 能力**——它是纯规则的。这样即使 P2 的 Agent 效果不佳，监控功能仍然可用。

### 为什么 P7b-1 无法提前并行（已核实修正）

原计划设想：若券商模拟环境门槛低于实盘量化权限，`QMTAdapter` 可提前到 P2-P6 并行验证，把最高工程风险挪出关键路径。

**2026-09-03 核实推翻了这个前提**（见 [00-overview](00-overview.md) 7.1a/7.1b）：**API 调用模拟盘与调用实盘用同一套量化接口权限**，券商不因为是模拟就降低审核。门槛最低 5 万（招商/东财）、国金 miniQMT 10 万、多数 50 万 + 6 个月实盘经验 + C4/C5 风测。所以拿到权限前连模拟盘 API 都调不了，`QMTAdapter` 无法提前验证。

**应对**：
- **A 股自动化链路的验证被迫后置到量化权限达成之后**，这是无法回避的约束
- 但 `QMTAdapter` 的**接口抽象、撮合假设、单元测试**仍可提前写（不依赖真实连接）
- **用美股 Alpaca Paper 通道先跑通端到端自动化链路**（注册即用、有沙盒），验证"Proposal → Risk → Execution"的代码路径，等 A 股权限达成时接的是"已验证的框架 + 新 Adapter"而非全新代码
- 权限达成前，A 股走「研究 + 人工执行清单」，见 [09-portfolio-risk](09-portfolio-risk.md) 第 6 节

撮合假设校准的独立价值仍然成立：`SimulatedBroker` 的涨跌停、成交量、集合竞价假设从未被真实撮合验证，回测与 Shadow 的结论都依赖它们——但这个校准同样只能等 A 股 API 权限达成后才能对着真实撮合做。

- Agent 幻觉 → 工具受限 + `check_figures_traceable`

### P2a — 规则监控与推送（1-2 周，零 LLM 成本）

**目标**：持仓异动主动推送，完全不用 LLM。

| 内容 | 说明 |
|---|---|
| 持仓手动维护 | YAML + CLI + 时效性检查 |
| 实时行情快照 Collector | 仅持仓 + 关注列表，3 分钟轮询 |
| A 类价格触发器 | 止损/止盈、涨跌停、停牌、放量异动、技术位破位 |
| B 类风控触发器 | 行业集中度、组合回撤、当日亏损、单股权重、现金比例 |
| C 类公告触发 | 纯规则，按公告类型分级 |
| 抑制策略 | 冷却期、每日上限、静默时段 |
| Telegram Notifier | 含反馈按钮 |
| `alert` 表与质量视图 | 各 trigger 的有用率统计 |

**关键设计**：P2a **完全不调 LLM**。先验证触发器是否有用、频率是否合适、用户是否会看。

**为什么先做纯规则**：如果 P2a 的推送有用率低于 40%，说明触发器设计有问题。此时加 LLM 只会放大问题并花钱。

### P2b — 智能分诊（2-3 周）

**目标**：新闻类触发的三级漏斗，成本可控。

| 内容 | 说明 |
|---|---|
| 实体别名词典 | 公司简称/全称/别称/产品名 → symbol |
| 关键词分级表 | critical / high / medium / none |
| L1 新闻过滤 | 实体匹配 + 关键词，零成本，通过率目标 < 5% |
| L2 小模型分诊 | 批处理（10 条/次）+ 极简输出 |
| L3 深度分析 | 复用 `StockAgent`，每日 ≤ 10 次 |
| 结果缓存 | 按内容哈希 + 持仓哈希 |
| 监控预算与降级 | 耗尽时降为 L1 纯规则 |
| 成本实测 | 写入 `cost-log.md` |
| 本地小模型评估 | L2 是否可本地化（可选） |

**关键产出**：日均监控成本 < $0.30，推送有用率高于 P2a。

**若加 LLM 后有用率未提升**，说明 LLM 层没产生价值，应回退到纯规则监控（省钱）。这是刻意设计的判断点。

### P3 — Quant 模型（4-6 周）

**目标**：从 baseline 逐级建立到 LightGBM。

| Level | 内容 |
|---|---|
| 因子扩充 | 从 8 个扩到 40+ 个（07 文档的完整清单） |
| L1 | 全部因子的单因子测试与准入筛选 |
| L2 | 多因子等权 / IC 加权组合 |
| L3 | Logistic / Ridge |
| L4 | LightGBM + Walk-forward + embargo |
| 诊断 | 特征重要性稳定性、参数敏感性 |
| 封存期 | 定义并锁定，不使用 |
| Feature Store | Parquet + DuckDB 增量更新 |
| 新增 shadow | `shadow_quant`（仅量化信号） |

**强制约束**：不允许跳级。L4 必须证明样本外优于 L2，否则不采用。

**主要风险**：过拟合。防范：`param_search_count` 记录、参数搜索空间受限、多轮 walk-forward 一致性检查。

### P4 — 完整回测与归因（3 周搭建 + 3 个月观察）

**目标**：建立可信的评估体系。这是项目分水岭。

| 内容 | 说明 |
|---|---|
| 完整回测引擎 | 全部撮合约束、成本模型、滑点模型 |
| 全部防偏差检查 | 08 文档的清单 |
| 对照组齐备 | 含蒙特卡洛随机选股 |
| Signal Fusion | 首版等权 + 相关性分析 |
| 归因分析 | 收益分解、信号贡献 |
| Agent IC 检验 | ★ 回答"Agent 有没有用" |
| Confidence 校准检验 | |
| 决策日志分析 | 分条件准确率 |
| 月度自评报告 | 自动生成 |
| 新增 shadow | `shadow_fused` / `shadow_fused_norisk` |
| **K3 自有判断历史（RAG）** | `v_thesis_with_outcome` → `document_chunk`。★ 需 A/B 验证 |
| **K4 经验教训沉淀** | 归因结论 + 失效模式，上限 50 条 |

**关键产出**：一份诚实的评估报告，说明系统在什么条件下可信。

**必须接受的可能结论**：Agent 层 IC 接近 0。此时降低其 Fusion 权重，保留解释与 red flag 用途，把 alpha 期望放在 Quant 层。**不要通过反复调 prompt 直到 IC 变正——那是过拟合。**

**为什么需要 3 个月观察**：Shadow Portfolio 的样本需要时间。这是唯一无法压缩的环节。

**为什么 K3 放在 P4**：历史 thesis 检索需要三个前置条件——足够的样本量（>100 条）、结果回填（`decision_outcome`）、归因分析。在 P2 就做等于检索几十条无结果的 thesis，没有信息量还要付费。

**K3 的 A/B 验证要求**：对比有无历史检索的 Agent 准确率。若只提升结论一致性而未提升准确率，说明是**锚定效应**而非学习，应关闭。见 [17-knowledge-base](17-knowledge-base.md) 5.4 节。

#### 为什么冷启动推荐放在 P5

**冷启动决定全部仓位，调仓只影响边际。所以它需要更完整的风控，不是更少。**

| 前置能力 | 缺了会怎样 |
|---|---|
| 相关性去冗余（P5） | 推荐 12 只同板块股票，看似分散实为一个赌注 |
| 波动率调整（P5） | 高波动标的权重过高 |
| 总仓位管理 stance（P5） | 不知道该买七成还是三成 |
| 全部 hard 风控（P5） | 推荐可能违反行业集中度约束 |
| Shadow 历史成绩（P4） | 无成绩可展示，无法对抗 R-24 |

A 股同概念板块内相关性极高，第一条不是理论风险。

**能力其实已存在**：3.2 节构建流程的 ①-⑥ 完全不参考现有持仓，本身就是"从零开始会持有什么"。冷启动不需要新 Agent、新模型（与不新建 MonitorAgent 同源）。需要新增的是三件事：

| 新增 | 原因 |
|---|---|
| 资金量约束 | A 股整手 100 股（科创板 200，需核实），小资金买不起 15 个等权持仓 |
| 分批建仓 | 一次性建仓让全部成本基础由一天价格决定，且污染归因 |
| `recommendation` 表 | 推荐 ≠ 实际持仓，需跟踪执行率，且归因必须用 shadow |

**这是整个系统里最接近"荐股"的功能**，会显著加剧 R-24（误当赚钱工具）。所以输出强制包含对照组表现、shadow 实际成绩、过往推荐的结果分布——**让用户看到的不是一份清单，而是一份带成绩记录的清单**。

详见 [09-portfolio-risk](09-portfolio-risk.md) 第 8 节与 [ADR-0013](adr/0013-cold-start-portfolio.md)。

### P7b-1 — A 股模拟环境验证（2-3 周，一旦模拟环境可得即可开始）

**前置**：券商模拟交易环境可用（**门槛需核实**，可能低于实盘量化权限）。

**这个阶段不必等到 P7。** 一旦模拟环境可得，就可以与 P2-P6 并行推进。

| 内容 | 说明 |
|---|---|
| `QMTAdapter` 实现 | Windows 进程 + IPC 架构 |
| 在模拟环境跑通全链路 | 下单 → 状态回报 → 成交 → 持仓 → 对账 |
| 20 项异常路径在真实 API 上验证 | **非 mock**。这是自建模拟器做不到的 |
| xtquant 幂等行为确认 | 重复提交同一 `client_order_id` 的实际行为 |
| 进程重启恢复验证 | IPC 断连、QMT 客户端崩溃后的状态恢复 |
| **撮合假设校准** | ★ 见下 |

**为什么要单独设这个阶段**：`QMTAdapter` 是全项目工程风险最高的组件（Windows 约束、IPC、公开文档少）。若它首次上线就接实盘，等于把最不确定的组件放在最高风险的位置。

**撮合假设校准**（见 [10-execution](10-execution.md) 3.4 节）：

`SimulatedBroker` 里有一批假设——涨停不可买入、成交量上限、集合竞价规则、部分成交处理。**回测和 Shadow Portfolio 的全部结论都建立在这些假设上，而它们从未被真实撮合验证过。** 单元测试只能验证代码符合我的假设，不能验证假设符合现实。

```
同一组订单 ──┬──▶ SimulatedBroker   → fills_sim
             └──▶ 券商模拟环境       → fills_real
                        ↓
                逐项对比，记录偏差
                        ↓
        若某项假设错误 → 修正 SimulatedBroker
                       → ★ 重跑全部历史回测
                       → 若结论翻转，此前评估全部无效
```

最后一条是这件事真正的价值：**它可能推翻已有结论。越晚做，需要推翻的越多。**

**关键产出**：`QMTAdapter` 在真实 API 上稳定运行 ≥1 个月；一份撮合校准报告。

### P7b-2 — A 股实盘（视权限条件）

**前置**：Gate 7b 通过（含 P7b-1 全部内容）+ 券商量化权限达成 + 程序化交易报告完成。

与 P7a 相同的渐进放权节奏：

```
全部人工确认  ──1个月无异常──▶  小额自动+大额确认  ──3个月无异常──▶  全自动+告警
```

**为什么 A 股不能比美股更宽松**：A 股规则更复杂（T+1、涨跌停、多板块不同幅度、ST 规则），且 `QMTAdapter` 的技术栈风险高于 Alpaca REST API。准入应更严，不是更松。

**同花顺/东财等免费模拟炒股对本项目没有价值，甚至有害。**

| 原因 | 说明 |

| 已被覆盖 | 策略层面的模拟，Shadow Portfolio 做得更严格 |

见 [ADR-0012](adr/0012-cn-simulated-trading.md)。

## 3. Gate 制度

### 3.1 为什么需要 Gate

防止"看起来能跑就进入下一阶段"。每个 Gate 是一组可客观验证的条件，不通过就不进入下一阶段。

**Gate 不通过时的正确动作是回头修，不是绕过。**

## 4. 不可跳过的环节

| 环节 | 为什么不能跳 |
|---|---|
| PIT 数据设计 | 后补等于重做全部回测 |
| 未来函数哨兵测试 | 唯一能自动发现泄漏的手段 |
| Buy&Hold 基线 | 没有参照，任何结果都无意义 |
| 单因子测试 | 验证回测引擎正确性的手段 |
| L2 等权基线 | 判断复杂模型是否值得 |
| 封存期 | 唯一真正客观的样本外 |
| Shadow Portfolio 早启动 | 需要真实时间，无法压缩 |
| Agent IC 检验 | 否则不知道 Agent 是否有用 |
| 异常路径测试 | 实盘出错的代价是真金白银 |
| 对账 | 状态不一致会导致连环错误 |
| 监控规则层零 LLM 依赖 | 预算耗尽时止损告警仍须工作 |
| **撮合假设校准** | 回测与 Shadow 的全部结论都建立在未验证的假设上 |
| **`QMTAdapter` 先跑模拟环境** | 工程风险最高的组件不应首次上线即接实盘 |
| **推荐清单自带成绩单** | 冷启动是最像荐股的功能，无成绩记录会放大 R-24 |

## 6. 退出条件

预先定义什么情况下应该停止或大幅调整，避免沉没成本谬误。

| 条件 | 动作 |
|---|---|
| Gate 4 显示 Quant 与 Agent 的 IC 均不显著 | 停止实盘计划，转为纯研究工具 + 监控告警 |
| Shadow 6 个月表现显著劣于基准 | 回到 P3 重新审视因子与模型 |
| LLM 成本无法压到可接受范围 | 削减 Agent 层，保留 P2a 纯规则监控 |
| P2b 加 LLM 后推送有用率未提升 | 回退到纯规则监控，省掉这部分成本 |
| 推送有用率持续 < 30% | 重新设计触发器或关闭推送功能 |
| 数据源持续不稳定，无法保证质量 | 考虑付费数据源或缩小范围 |
| **撮合校准显示假设严重错误且修正后结论翻转** | 回到 P4 重新评估，此前全部结论作废 |
| **推荐执行率持续 < 30%** | 推荐不可执行（资金/整手/涨停），调整参数或缩小适用资金区间 |
| 实盘连续 3 个月亏损且超出回测预期 | 触发 kill switch，暂停并复盘 |
| 投入产出比不可接受 | 保留研究价值，停止实盘投入 |

预先写下这些条件，是为了在情绪化的时刻有客观依据。

注意第 3、4 条：**即使全部 LLM 功能都被证明无价值，P2a 的纯规则监控依然有独立价值**（止损提醒、跌停告警、关键公告推送）。这是把监控规则层做成零 LLM 依赖的额外好处——它是整个系统里最不容易失败的部分。

撮合校准那一条是最不想触发但必须预设的：它意味着回测层面的努力白费。**这正是应该尽早做校准的理由**——越晚发现，作废的越多。
